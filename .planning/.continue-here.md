# BLOCKING CONSTRAINTS: Read Before Anything Else

> Each constraint below was discovered through an actual failure this session.

- [ ] CONSTRAINT: Tool-input escape conversion. `\uXXXX` escapes typed into Write/Edit/heredoc content were stored as the LITERAL characters, including invisible ones like ZWJ and FE0F, in `ai_cleanup/text.py`. Mitigation: write non-ASCII in source via `chr(0x...)`, or generate escapes with `chr(92)` in a script. After any edit, audit with `python3 -c "s=open(F,encoding='utf-8').read(); print({hex(ord(c)) for c in s if ord(c)>127})"`.
- [ ] CONSTRAINT: Qt worker-thread shutdown. `_on_done` called `thread.wait()` before the queued `thread.quit()` ran, which deadlocked the GUI. Mitigation: always `quit()` then `wait()` in the main-thread slot.
- [ ] CONSTRAINT: No AI attribution in commits or PRs (user memory rule). Do not add Co-Authored-By lines.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Literal invisible chars in source | Escapes became raw chars via the tool layer | blocking | Non-ASCII audit after every source edit (see above) |
| wait-before-quit on QThread | GUI hang after a batch finished | blocking | `quit()` before `wait()`; run an offscreen smoke test (`QT_QPA_PLATFORM=offscreen PYTHONPATH=.`) |
| `&` in Qt labels | Rendered as a mnemonic ("Metadata _provenance") | advisory | Use `&&` in QCheckBox/QPushButton text |
